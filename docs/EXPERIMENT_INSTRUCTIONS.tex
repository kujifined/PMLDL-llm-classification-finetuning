\section*{1. Подготовка среды (один раз)}

\begin{enumerate}[leftmargin=*,itemsep=0.7em]
  \step{Склонируйте репозиторий.}
  \begin{lstlisting}[style=terminal]
git clone https://github.com/kujifined/PMLDL-llm-classification-finetuning.git
cd PMLDL-llm-classification-finetuning
  \end{lstlisting}
  \why{создаётся локальная рабочая копия проекта.}

  \step{Установите зависимости.}
  \begin{lstlisting}[style=terminal]
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-baseline.lock
python -m pip install -e . --no-deps
python -m pip install clearml nbclient nbformat
  \end{lstlisting}
  \why{подготавливается одинаковое окружение для всех участников.}

  \step{Подключите ClearML.}
  \begin{lstlisting}[style=terminal]
clearml-init
  \end{lstlisting}
  Введите личные ключи ClearML. \why{эксперимент будет виден в общем проекте команды.}
\end{enumerate}

\section*{2. Проведение эксперимента}

\begin{enumerate}[leftmargin=*,itemsep=0.8em]
  \step{Создайте эксперимент.}
  \begin{lstlisting}[style=terminal]
make new-experiment
  \end{lstlisting}
  Ответьте на вопросы мастера и сохраните выведенный \texttt{ID}.
  \why{команда создаёт ветку, конфигурацию и личный ноутбук.}

  \step{Измените код.}
  Откройте созданный ноутбук в \texttt{output/jupyter-notebook/} и измените
  только функцию \texttt{train\_and\_evaluate}. Seed, split и метрики не меняйте.
  \why{так фиксируется только ваша экспериментальная идея.}

  \step{Запустите smoke-тест и полный эксперимент.}
  \begin{lstlisting}[style=terminal]
make run-experiment EXPERIMENT=<ID>
  \end{lstlisting}
  Сначала проверяется короткий smoke-запуск, затем автоматически выполняется
  полный. При ошибке исправьте указанную ячейку и повторите ту же команду.
  \why{ошибки находятся до долгого обучения, а запуск логируется автоматически.}

  \step{Проверьте сохранённые данные.}
  Метрики находятся в \texttt{results/runs/}, большие файлы --- в
  \texttt{artifacts/}, live-метрики --- в проекте ClearML
  \texttt{PMLDL LLM Classification Finetuning}.
  \why{можно убедиться, что run завершён и результаты доступны команде.}

  \step{Зафиксируйте результат и отправьте ветку.}
  \begin{lstlisting}[style=terminal]
make submit-experiment EXPERIMENT=<ID>
  \end{lstlisting}
  Команда проверяет run, обновляет \texttt{results/leaderboard.csv}, создаёт
  commit, отправляет ветку на GitHub и печатает ссылку на Pull Request.

  \step{Создайте Pull Request.}
  Откройте напечатанную ссылку GitHub и дождитесь успешного прохождения CI.
  \why{после проверки результат попадает в общую историю проекта.}
\end{enumerate}

\section*{Перед Pull Request}

\begin{itemize}[leftmargin=*,itemsep=0.35em]
  \item full-run имеет статус \texttt{completed};
  \item метрики записаны в \texttt{metrics.json};
  \item результат виден в ClearML и leaderboard;
  \item данные Kaggle, токены, checkpoints и `.env` не добавлены в Git.
\end{itemize}
